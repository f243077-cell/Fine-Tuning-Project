# Model card: ru-guard-1.5b-v2 (draft, Phase 5)

A small prompt-injection classifier for Roman Urdu, English and mixed text. It reads one text window and its source, and answers with one label. It is meant to run locally behind `guard-api`. It is a guard, not a content-safety model.

## Model

| Item | Value |

| Method | QLoRA (Unsloth 2026.11.4, TRL 1.15.0, PEFT 0.21.3): r 16, alpha 32, dropout 0.05, lr 2e-4 cosine, warmup 0.03, 3 epochs, effective batch 32, max length 512, seed 1234, assistant-only loss (D45) |

## Input and output

- Input: the fixed system prompt (`training/prompt.py`), then one user turn with the source (`user_input`, `retrieved_chunk` or `tool_output`) and the normalized text window (`training/normalize.py`).
- Output: `SAFE` or `INJECTION|<attack_type>`, where attack_type is `override`, `persona`, `prompt_leak`, `exfiltration` or `tool_abuse`. Anything else is invalid and must be treated as a flag (fail closed).

## Intended use

- Screening user input, retrieved chunks and tool outputs before they reach an LLM in a RAG app, agent or MCP gateway, for users who write Roman Urdu, English or a mix.
- Local, offline use on a CPU through `guard-api`.

Out of scope: Urdu in Arabic script, other languages, content-safety moderation (hate, self-harm and so on), jailbreak detection in model outputs, and use as the only security control.

## Why this model (D49)

- Best recall, F1 and attack-type macro-F1 of all models measured on the CPU, with no invalid output.
- It is the only model that meets the `en` to `ru_pure` recall-gap target (6 points against 10) and the Roman Urdu recall target (0.94 against 0.90).
- Q4_K_M rather than Q8_0: the owner chose the smaller file for a faster download from Kaggle. On the first v2 training run (Kaggle GPU) Q8_0 had 2 points more recall (0.987 vs 0.967); Q4_K_M is about 10% faster on the CPU (measured on v1).
- The 0.5B models are not clearly faster on this CPU (warm p50 3.07 s for v1 0.5b vs 3.29 s for 1.5b-v2) but miss more Roman Urdu attacks (0.5b-v2: `ru_pure` recall 0.86, FPR 0.127).

## Limitations

- **False positives on hard negatives.** FPR 0.179 on benign text that talks about instructions, rules, prompts or role-play (target FPR <= 0.03 is missed). Use `MODE=log_only` or per-source policy where blocking benign text is costly.
- **Guard-targeting attacks.** Text that tells the classifier to answer SAFE is the main source of misses (5 of 7).
- **Synthetic training data.** Attacks were generated by Qwen2.5-14B and converted to `ru_pure` by a dictionary; real spellings vary more.
- **Small test set.** CIs are 5 to 15 points wide.
- **Weights are not bit-reproducible.** The deployed file is a second training run of the same config; the GGUF hash above identifies it.

## Ethics and safety

All attack examples use harmless placeholders (reveal the system prompt, say a secret word, call a harmless tool). The guard logs only a keyed hash and length of scanned text, never raw text (Phase 6). A guard lowers risk; it does not make an LLM app safe on its own.
